# 宝塔部署：Vue 官网 + ShopXO 独立订单中心

## 选型和接入边界

- 官方仓库：https://github.com/gongfuxiang/shopxo 。入口源码审阅基线为 `v6.9.1`，标签对应提交 `e55db292b07b3406049b41dad216da6fa568ac57`；不要直接部署未经核对的 master。
- 截至 2026-10-22 再次核对，官网发布历史已列出 2026-09-28 的 `v6.9.2`，本次读取的 GitHub 标签列表仍以 `v6.9.1` 开头。不能把 GitHub 最高标签误称为最新官方版；正式安装前应从官方渠道获取拟安装版本、核对来源/校验值和安全修复，再复核入口兼容性。官方信息：https://shopxo.net/download.html 。
- 本仓库新增的准备命令只锁定上述开发基线，不代表 v6.9.1 是最新安全版本或可以原样上线。此处没有完成全量安全审计。历史版本存在上游安全问题报告；不能仅凭采用开源方案就承诺安全。安装前检查目标版本与 PHP/Composer 依赖的安全补丁，限制后台、安装器、计划任务和上传执行权限。
- 核心源码为 MIT 许可证，需保留版权与许可证。应用商店插件、主题、独立 H5/小程序客户端可能有不同授权，不能据核心开源推断全部免费。
- 官网保留现有 Vue/SSG；订单中心单独使用 ShopXO 的 PHP + MySQL 账户、商品、订单和支付。第一阶段为原生页面入口集成，**不是**在 Vue 内实现 ShopXO 的登录、购物车或订单 API。
- 多端查看依赖同一账户：在不同电脑/手机浏览器登录相同账户查询。旧 Node 订单没有自动绑定或迁移；不能靠同邮箱或订单号直接授权。
- 官方代码包含电脑网站、手机网站和 App 支付分支，但商户要分别具备对应产品资格。只开通电脑网站支付不能宣称手机浏览器 WAP 支付也能使用。
- 价格、可购买状态、服务交付说明、条款、收款方和付款状态仅以 ShopXO 下单快照为准。官网不创建镜像订单、不写另一套支付回调。

## 本地二开工程（已提供，不只是官网外链）

```bash
npm run orders:prepare
# 如果已取得同一官方归档，可离线准备；仍然强制校验 SHA-256：
npm run orders:prepare -- --archive /绝对路径/shopxo.tar.gz
# 默认输出目录已存在时拒绝覆盖，可以另选一个全新目录：
npm run orders:prepare -- --output /绝对路径/新的订单中心目录
```

- `upstream.lock.json` 固定仓库、提交、归档 SHA-256 和关键源文件摘要；保留上游 MIT 许可证。不执行归档里的安装脚本、不自动连接数据库、不修改官网 `.env.local`。
- 输出为 `artifacts/order-center/shopxo/`，含上游账户、订单、管理后台及 `patches/0001-alipay-backoffice-environment.patch` 的改动。生成的第三方源码不提交到官网仓库，维护固定来源和可复现补丁。
- 二开复用原生支付管理表单：新增沙箱/正式环境、收款方 PID、手机网站支付产品开关；支付网关采用固定白名单，HTTPS 请求开启证书及主机名校验，并设连接/总超时。回调补充应用/收款方/RSA2 校验，不用同步回跳确认付款。原生订单金额核对、事务和账户权限仍由 ShopXO 处理，不能据源码推断真实支付已通过。
- `mono-service-catalog.json` 从官网现有三项服务生成，价格以整数分转换。它是**待确认的商品资料，不是数据库导入结果**。不自动上架，不自动创建客户或交易。
- `mono-source-manifest.json` 记录来源、补丁和 PHP 语法检查状态。无本地 PHP 时明确记为 `not-run-php-unavailable`；源码准备成功不等于 PHP/MySQL 运行、登录或支付验收完成。
- 当前只适配普通公钥 `Alipay` 插件。不要安装未经本次适配的 `AlipayCert` 后宣称同样具备沙箱与校验能力；如实际商户采用证书模式，另行适配和验证。

## 支付信息在订单后台配置

采用 ShopXO 模式后，支付凭据只在**订单中心管理后台 → 支付方式 → 支付宝**填写，不再使用官网 `.env.payment.local` 管理新交易：

| 配置项 | 用途 |
|---|---|
| 支付环境 | 默认沙箱；真实支付必须显式选择正式环境 |
| 应用 ID / 收款方 PID | 对应当前环境的应用和实际收款方，回调也核对这两项 |
| 应用公钥 / 应用私钥 / 支付宝公钥 | 使用同一环境、同一应用的配套凭据，支持上游公钥接入模式 |
| 手机网站支付产品 | 默认仅电脑网站支付；只有另行开通并验证 WAP 后才能选择同时开通 |
| 是否启用 / 适用终端 | 使用原生后台通道开关；先联调，最后开启对用户收款 |

先在新实例安装本二开源码，再从后台安装/配置支付宝插件，才能取得新增的表单字段。已有线上 ShopXO 不能只替换 PHP 文件就视作数据库配置定义已升级，更不能卸载仍接收旧订单通知的支付插件；需另做备份、配置定义迁移和回归。

上游原生后台将这些配置保存在订单中心数据库，并对有支付管理权限的管理员回显。**本次没有把它改成密钥保险箱，也没有完成字段加密或密钥轮换改造**：必须限制后台管理员/数据库/备份访问，使用 HTTPS 和受保护的备份；不得把数据库备份、配置截图或私钥放进官网或发到聊天里。后续微信继续使用订单中心支付方式管理，但微信插件、商户产品和实际回调需要单独验收，本次不默认开启。

## 部署前必须确认

1. 服务器 IP/SSH 用户/本地密钥路径及授权；执行 `cat /etc/os-release` 确认是否 Alibaba Cloud Linux 和实际版本。
2. 确认既有宝塔站点、Nginx/PHP/MySQL 版本、磁盘/内存、备份和可用域名；不覆盖现有站点，不另开放数据库公网端口。
3. 准备一个实际订单中心子域名（本文不猜测正式域名），解析到服务器；设置 HTTPS 证书。使用原生顶层跳转，无需把登录 Cookie 跨域共享给官网。

## 宝塔安装顺序

1. 备份现有站点及数据库；新增独立 PHP 站点及独立 MySQL 数据库/用户，禁止复用 root 数据库账号。
2. 从官方固定标签/提交获取源码；按该版本安装文档选择运行目录、PHP 版本和扩展。其 Composer 契约要求 PHP >=8.0，具体版本、PDO/MySQL、文件读写和扩展由安装器与依赖检查确认；不盲目升级现有站点 PHP。
3. 安装前仅允许运维 IP 访问；为后台设置独立强密码、限制访问来源；完成安装后按上游要求锁定/关闭安装入口和调试输出。用户上传目录不得执行 PHP。数据库、备份和密钥不能通过 HTTP 下载。
4. 创建实际服务商品，尽量使用上游支持的虚拟/服务销售模式，不伪造物流。同步本项目三项服务的范围、交付、排除项与联系资料采集；确认真实价格和服务条款。
5. 在独立测试实例联调支付，后台保存真实商户配置，私钥不得进入官网的 VITE_* 或聊天。上游原版 v6.9.1 插件固定正式网关；本二开补丁增加了后台环境切换，但尚未用真实沙箱凭据联调。必须确认部署的是带补丁源码、后台选中沙箱并填写沙箱凭据，验证通过后再执行经授权的正式小额验收。保持新支付关闭直到签名、商户/金额、通知、查单与退款核验通过。
6. 为 PHP/MySQL 配置持久数据和宝塔一致性数据库备份，并将备份另存可信位置。不要在静态目录里保存 SQL 备份，也不要将 MySQL 数据文件直接复制当作完整备份。

## 官网入口配置

ShopXO 安装、商品配置和登录验收完成后，在官网构建环境中配置：

```dotenv
VITE_SHOPXO_ORIGIN=https://your-verified-order-domain.example
# 下列数字仅展示 JSON 格式，必须替换为后台真实商品 ID。
VITE_SHOPXO_PRODUCTS={"technical-review":101,"page-improvement":102,"api-integration":103}
```

- 必须配置全部三项，商品 ID 为不同正整数；缺失、非法域名或非法映射会阻止构建。
- 原生路由以 v6.9.1 控制器为依据：`/index.php?s=/index/goods/index&id=商品ID`、`/index.php?s=/index/order/index`。必须在部署实例核对路由；不要假定后台安装完成就能立即购买。
- 配置生效后，商城卡片转到订单中心商品页；官网确认订单页不再创建 Node 订单；订单查询页进入账户订单中心。官网隐藏旧静态金额，避免与订单中心实时售价冲突。
- 未配置时保留原 Node 服务路径，仍是浏览器凭证查询，**不是跨设备模式**。不要同时启用两套新交易入口。迁移已有订单须另做可审计的身份核验与数据映射。
- 重新 `npm run build`，只发布 `dist/` 到既有官网目录；不必为了 ShopXO 开通而部署 Node 服务。

## 上线验收

- 电脑创建订单；在手机/另一个浏览器登录同一账号可查看相同订单，其他账号和未登录用户不可查看详情。
- 核对服务映射、实时价格、条款、支付宝真实收款方、通知到达、主动查单、重复通知和取消/退款；不要将浏览器回跳当作支付证明。
- 检查桌面/窄屏、订单中心回官网入口、上传执行保护、后台和安装器访问限制，以及备份恢复。
- 手机网站支付宝付款必须单独验证已开通的手机网站支付产品；原生 App/小程序不在本次入口集成范围。

当前已提供可复现的 ShopXO 二开源码准备、后台支付环境字段和官网入口；尚未安装 PHP/MySQL 运行实例或远端 ShopXO，也未验证跨设备真实账号与支付宝交易。以上验收不能由本地 mock 测试代替。
