# 宝塔部署：Vue 官网 + ShopXO 独立订单中心

## 选型和接入边界

- 官方仓库：https://github.com/gongfuxiang/shopxo 。入口源码审阅基线为 `v6.9.1`，标签对应提交 `e55db292b07b3406049b41dad216da6fa568ac57`；不要直接部署未经核对的 master。
- 截至 2026-10-10，官网发布历史已列出 2026-09-28 的 `v6.9.2`，本次读取的 GitHub 标签列表仍以 `v6.9.1` 开头。不能把 GitHub 最高标签误称为最新官方版；正式安装前应从官方渠道获取拟安装版本、核对来源/校验值和安全修复，再复核入口兼容性。官方信息：https://shopxo.net/download.html 。
- 此处没有完成全量安全审计。历史版本存在上游安全问题报告；不能仅凭采用开源方案就承诺安全。安装前检查目标版本与 PHP/Composer 依赖的安全补丁，限制后台、安装器、计划任务和上传执行权限。
- 核心源码为 MIT 许可证，需保留版权与许可证。应用商店插件、主题、独立 H5/小程序客户端可能有不同授权，不能据核心开源推断全部免费。
- 官网保留现有 Vue/SSG；订单中心单独使用 ShopXO 的 PHP + MySQL 账户、商品、订单和支付。第一阶段为原生页面入口集成，**不是**在 Vue 内实现 ShopXO 的登录、购物车或订单 API。
- 多端查看依赖同一账户：在不同电脑/手机浏览器登录相同账户查询。旧 Node 订单没有自动绑定或迁移；不能靠同邮箱或订单号直接授权。
- 官方代码包含电脑网站、手机网站和 App 支付分支，但商户要分别具备对应产品资格。只开通电脑网站支付不能宣称手机浏览器 WAP 支付也能使用。
- 价格、可购买状态、服务交付说明、条款、收款方和付款状态仅以 ShopXO 下单快照为准。官网不创建镜像订单、不写另一套支付回调。

## 部署前必须确认

1. 服务器 IP/SSH 用户/本地密钥路径及授权；执行 `cat /etc/os-release` 确认是否 Alibaba Cloud Linux 和实际版本。
2. 确认既有宝塔站点、Nginx/PHP/MySQL 版本、磁盘/内存、备份和可用域名；不覆盖现有站点，不另开放数据库公网端口。
3. 准备一个实际订单中心子域名（本文不猜测正式域名），解析到服务器；设置 HTTPS 证书。使用原生顶层跳转，无需把登录 Cookie 跨域共享给官网。

## 宝塔安装顺序

1. 备份现有站点及数据库；新增独立 PHP 站点及独立 MySQL 数据库/用户，禁止复用 root 数据库账号。
2. 从官方固定标签/提交获取源码；按该版本安装文档选择运行目录、PHP 版本和扩展。其 Composer 契约要求 PHP >=8.0，具体版本、PDO/MySQL、文件读写和扩展由安装器与依赖检查确认；不盲目升级现有站点 PHP。
3. 安装前仅允许运维 IP 访问；为后台设置独立强密码、限制访问来源；完成安装后按上游要求锁定/关闭安装入口和调试输出。用户上传目录不得执行 PHP。数据库、备份和密钥不能通过 HTTP 下载。
4. 创建实际服务商品，尽量使用上游支持的虚拟/服务销售模式，不伪造物流。同步本项目三项服务的范围、交付、排除项与联系资料采集；确认真实价格和服务条款。
5. 在独立测试实例联调支付，后台保存真实商户配置，私钥不得进入官网的 VITE_* 或聊天。审阅的 v6.9.1 支付宝插件使用固定正式网关、未看到环境切换配置；**不能直接将沙箱密钥填入它并宣称沙箱可用**。需先验证目标版本/插件支持的沙箱能力，必要时单独适配，再执行经授权的正式小额验收。保持新支付关闭直到签名、商户/金额、通知、查单与退款核验通过。
6. 为 PHP/MySQL 配置持久数据和宝塔一致性数据库备份，并将备份另存可信位置。不要在静态目录里保存 SQL 备份，也不要将 MySQL 数据文件直接复制当作完整备份。

## 官网入口配置

ShopXO 安装、商品配置和登录验收完成后，在官网构建环境中配置：

```dotenv
VITE_SHOPXO_ORIGIN=https://your-verified-order-domain.example
# 下列数字仅展示 JSON 格式，必须替换为后台真实商品 ID。
VITE_SHOPXO_PRODUCTS={"technical-review":101,"page-improvement":102,"api-integration":103}
```

- 必须配置全部三项，商品 ID 为不同正整数；缺失、非法域名或非法映射会阻止构建。
- 原生路由以 v6.9.1 控制器为依据：`/index.php?s=/index/goods/index&id=商品ID`、`/index.php?s=/index/order/index`。必须在部署实例核对路由；不要假定后台安装完成就能立即购买。
- 配置生效后，商城卡片转到订单中心商品页；官网确认订单页不再创建 Node 订单；订单查询页进入账户订单中心。官网隐藏旧静态金额，避免与订单中心实时售价冲突。
- 未配置时保留原 Node 服务路径，仍是浏览器凭证查询，**不是跨设备模式**。不要同时启用两套新交易入口。迁移已有订单须另做可审计的身份核验与数据映射。
- 重新 `npm run build`，只发布 `dist/` 到既有官网目录；不必为了 ShopXO 开通而部署 Node 服务。

## 上线验收

- 电脑创建订单；在手机/另一个浏览器登录同一账号可查看相同订单，其他账号和未登录用户不可查看详情。
- 核对服务映射、实时价格、条款、支付宝真实收款方、通知到达、主动查单、重复通知和取消/退款；不要将浏览器回跳当作支付证明。
- 检查桌面/窄屏、订单中心回官网入口、上传执行保护、后台和安装器访问限制，以及备份恢复。
- 手机网站支付宝付款必须单独验证已开通的手机网站支付产品；原生 App/小程序不在本次入口集成范围。

当前只有官网入口与部署准备，未安装远端 ShopXO，也未验证它与真实支付宝交易。以上验收不能由本地 mock 测试代替。
