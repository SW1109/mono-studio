# 2026-10-22 项目全面检查与更新

范围：官网导航与商品页面、Node 订单/支付接口、ShopXO 入口和已有支付补丁、运行环境、配置管理、构建与发布。此记录描述本地执行结果，不等于已部署或已完成真实商户验收。

## 本轮修复

| 问题 | 处理 |
| --- | --- |
| 本机 Node 24.9.0 未达到 10 月安全版本基线 | 校验官方 SHA-256 后安装项目隔离 Node 24.22.1，开发服务、构建和测试已切换；未替换全局 Node。生产入口、npm 命令和 CI 增加版本要求。 |
| 首次下单响应丢失时可能尚未保存浏览器凭证，重试创建另一单 | 在加载可购买目录时建立 HttpOnly 会话；创建订单必须携带会话。确认重试使用相同幂等键且数据库仅一单。禁用 Cookie 时先提示恢复会话。 |
| 查询付款期间切换路由可能继续支付错误订单或访问空对象 | 绑定发起操作时的订单和页面代次；离开/切换即取消请求，旧结果不再触发付款。 |
| 更新价格后前端仍用旧编译报价校验 | 前端按刚获取的报价核对，服务端继续独立使用服务端目录计算与验证金额。 |
| ShopXO 接管后旧服务收款开关可能遗留 | 增加服务端 `PAYMENT_ORDER_CENTER=shopxo`；同目录启动也根据官网构建清单识别。关闭旧新单/付款入口，保留历史通知及查询。 |
| 支付查询整体读取后才检查响应大小，重复字段存在歧义 | 读取过程中限制响应字节数、取消超限流、不跟随重定向；按顶层原始 JSON 字节验签并拒绝重复/冲突封装字段。 |
| 格式错误目录可引起组件异常，网络失败只显示底层英文 | 增加目录、订单与金额字段检查及有界读取；显示网络/数据异常提示、重试与刷新价格入口，服务端字段错误定位输入框。 |
| 每个视频/HEAD 请求把整文件读入内存 | 静态文件改流式发送，视频按字节范围读取；HEAD 不读取正文，支持 ETag/304、If-Range、416。 |
| 静态目录可能暴露隐藏文件或越界链接 | 隐藏路径拒绝，文件真实路径须留在静态目录内；无效编码返回 400，未知页面返回 404。 |
| `.env.local` 原先由 Git 跟踪 | 从索引移除并加入忽略，本地文件保留；历史提交未改写。 |
| 文档里的运行时、页面数及验收状态陈旧 | 更新开发/部署说明、发布清单和 CI；加入真实 Chrome 的隔离浏览器回归。 |

## 运行时和依赖

- Node 版本策略：`server/node-security-policy.json`，官方公告 https://nodejs.org/en/blog/vulnerability/october-2026-security-releases 。已核对 22.23.4、24.22.1、26.12.1，各分支分别判断，不接受未审核分支/预发行版本。本机官方 Windows 压缩包 SHA-256：`d2046d28c2c3dcd211ac5145c0bf30e2047ef9dfb306693c8c6e2eccd8b95fa5`。

- npm 全依赖 audit 与 Composer 生产锁 audit 均无已知漏洞告警。安全扫描结果不涵盖所有业务缺陷。
- 当前兼容范围内依赖已安装锁定版本。Cesium 1.146、Vite 8、Vue Router 5、Unhead 3 的迁移不混入本轮；其 API/构建/地图展示兼容性需单独验证。保留已测依赖锁。
